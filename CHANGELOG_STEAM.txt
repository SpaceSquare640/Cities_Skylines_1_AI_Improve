[h1]2026-08-17 - Important fire response fix[/h1]
[list]
[*] [b]Fixed emergency helicopters being grounded (and airports closed) indefinitely after a thunderstorm ended.[/b] The check for "is a thunderstorm happening" only tested whether a disaster record still existed, not whether it was still running - and a finished storm's record lingers long after the weather clears. Measured in one 62-minute session: emergency helicopters were refused dispatch in 55 of those minutes continuously and airports refused over 13,000 landings. Because fire helicopters are grounded along with the other emergency helicopters, [b]this is why burning buildings could get no response at all[/b]. It now uses the same test the game itself uses, so a storm only counts while it is genuinely in progress.
[*] [b]Fixed a growing slowdown around fire dispatch.[/b] The list of known burning buildings was never cleaned up - every building that had ever caught fire stayed in it for the rest of the session, and that whole list is re-scanned every time a fire vehicle looks for another fire to attend. It now drops buildings once their fire is out.
[*] [b]Much smaller logs.[/b] Several per-vehicle diagnostics were still writing to the log even with Verbose logging turned off. In one player's session those accounted for 90% of the mod's entire log output. They now respect the Verbose logging switch like everything else.
[/list]

[h1]2026-08-16 - Two real bug fixes[/h1]
[list]
[*] [b]Fires could go completely unserviced when Transfer Manager CE is installed.[/b] Once the fire responder cap was hit, this mod handed target selection to TMCE and trusted it to eventually try a different building - in practice, TMCE could keep sending fresh trucks/helicopters back to the exact same already-full building indefinitely, so the fire never got a real responder. Now tracks consecutive failed hand-offs per building and, past a threshold, picks an alternate burning building itself instead of continuing to trust TMCE.
[*] [b]Settings could silently fail to load correctly on startup.[/b] A C# initialization-order issue meant some internal state was reading a value before the save file had finished registering. Fixed by guaranteeing registration always runs first.
[/list]

[h1]2026-08-15 - Settings UI, per-feature toggles, tuning sliders[/h1]

This update adds a real settings interface. Every individual feature - not just broad categories - can now be turned on or off on its own, most of the numbers behind those features are adjustable, and the interface is available in English, 繁體中文 and 简体中文.

[h2]New: settings interface[/h2]
[list]
[*] [b]Full settings page[/b] - ESC → Options → Content Manager → Mods → AI_Improve. Twelve sections are picked from a list down the left side (General, Emergency, Metro, Intercity Trains, Aircraft, Local Transport, Intercity Buses, Cargo & Ships, Citizens & Races, Citizen Transport AI, Advanced, About); most sections split into a Toggles tab and a Tuning tab across the top, so a feature's switch and the values that affect it sit together.
[*] [b]Every slider (and Verbose logging) now has a hover tooltip[/b] explaining what the number actually does in plain language, not just its name.
[*] [b]Quick in-game panel[/b] - adds an AI_Improve button to the [url=https://steamcommunity.com/sharedfiles/filedetails/?id=2966990700]UnifiedUI[/url] toolbar for the empty-vehicle scan tools below, without leaving your city. Full toggle/tuning control lives in Content Manager. UnifiedUI is optional; without it Content Manager is still the only way in.
[*] [b]22 independent feature toggles[/b], up from the original 9 broad categories - e.g. the fire responder cap and the idle-truck nearby-fire search are now separate switches, as are metro rerouting, intercity train platform assignment, intercity train rerouting, and the low-ridership spawn throttle (previously all one "trains" switch).
[*] Turning a feature off makes it behave exactly as if it had never been written - the game's own original code runs untouched.
[*] [b]Multi-language[/b] - follows your game language automatically, or pick English, 繁體中文 or 简体中文 from the language dropdown on the General page. Each language is listed in its own script, so you can find yours even if the current interface language is unreadable to you.
[*] The header shows when the build was last updated, so you can tell at a glance whether your copy is current.
[/list]

[h2]New: adjustable values[/h2]
[b]26 sliders[/b] covering nearly every number the mod used to hardcode - fire responders per building and uncap timer, reroute density thresholds (per vehicle type), train station saturation/platform candidates, aircraft gate capacity/candidates, citizen car/taxi behavior, race complex attractiveness, reroute cooldown/check interval, and more. Defaults match the old fixed values exactly, so nothing changes until you move one.

[h2]New: Citizen Transport AI (off by default)[/h2]
A new "Citizen Transport AI" section with one switch and 4 weight sliders - Walk, Drive, Taxi, Transit - that decide how each citizen picks a way to get around, replacing vanilla's own fixed age-based car/taxi/bike odds entirely while active.
[list]
[*] Walk and Transit cover every public transport type together (bus, metro, train, everything else) - vanilla has no point where a citizen chooses a specific transit type, the pathfinder mixes whatever lines are available into one route, so a single combined weight is what's actually controllable.
[*] Setting Walk to 100 genuinely forces walk-only trips (no vehicle, no transit) using the same flag vanilla itself uses internally for this. Transit at 100 means transit is always allowed, not literally forced - there's no such thing as "must ride transit" in vanilla, and reaching a stop always requires some walking.
[*] [b]4 one-click presets[/b] on the Tuning tab: Balanced, Transit-oriented, Car-dependent, Walkable city.
[*] Off by default - turning it on is an active choice, since it fully replaces vanilla's decision instead of nudging it like the citizen car/taxi toggles above it do.
[/list]

[h2]New: ship dock assignment (on by default)[/h2]
Occupancy-aware dock assignment for cargo ships and passenger ferries, closing the one gap found while researching the freight/cargo AI - trains and aircraft already got this treatment previously (indirectly, via their shared base classes), ships never had. Spreads harbor traffic across a harbor's real dock capacity the same way trains/aircraft already spread across platforms/gates, instead of vanilla's blind pathfind piling every ship onto the same dock.

[h2]New: empty vehicle cleanup[/h2]
[list]
[*] Two buttons on the in-game panel scan for intercity trains / intercity buses currently carrying zero passengers, report how many were found, and delete them only if you confirm. Scanning by itself changes nothing.
[/list]

[h2]Fixes[/h2]
[list]
[*] [b]Important - empty vehicle scan could match your own train lines.[/b] The scan treated any non-metro passenger train as "intercity", which also matched player-created in-city train lines and monorail. If one of those trains happened to be empty when you ran a scan, it was offered up for deletion. It now correctly matches only trains arriving from outside connections. Your own train lines, metro, monorail and trams are never touched.
[*] Vehicles are also re-checked immediately before deletion, so a vehicle that picked up passengers while the confirmation dialog was open is skipped rather than removed.
[*] Vehicle deletion now runs on the simulation thread instead of the UI thread, removing a race condition that could corrupt internal state.
[*] Fixed the UnifiedUI button appearing as a detached grey box instead of joining the toolbar, on setups where several mods each bundle a different version of the UnifiedUI library.
[*] Fixed stale per-vehicle state surviving after a vehicle despawned. Because the game recycles vehicle IDs, a new vehicle could inherit a dead one's rerouting cooldown (blocking it from rerouting for up to 40 seconds) or its dispatch timestamp (producing wildly wrong emergency response times in the log).
[*] The settings page previously reported "Version 0.0.0"; it now shows the date the build was last updated, plus the exact source commit it came from.
[*] Fixed the fire responder cap still applying even when its toggle was turned off (while leaving the idle-truck nearby-fire search on) - it now correctly does nothing when disabled, matching every other toggle.
[*] [b]Removed the race car max speed override.[/b] Forcing every racer to the same flat top-speed ceiling could make them lose control on turns. Racer speed is fully vanilla again; the racetrack attractiveness boost is unaffected.
[*] [b]Fixed the toolbar button having no icon.[/b] The UnifiedUI registration was passing an icon file path that this mod never actually shipped, so the button always rendered blank. It now builds a small icon at runtime instead - no file involved.
[/list]

[h2]Performance[/h2]
[list]
[*] [b]Log output reduced by roughly 96%.[/b] Measured on a real city, over 2500 of the mod's ~2600 log lines in a single session came from one per-aircraft diagnostic - and every line is a disk write. Per-vehicle logging is now off by default, behind a [b]Verbose logging[/b] switch on the settings page's General section. Turn it on only when reproducing a problem for a bug report.
[*] Per-vehicle congestion checks are now spread across simulation ticks instead of every vehicle being checked every tick, cutting that hot path's cost substantially in large cities.
[*] Reordered the same hot path so the cheapest checks run first - a string lookup was running for every vehicle every tick, ahead of the very check meant to make that path cheap.
[/list]
